## 1. 已确认的目标与范围

在现有图片与可视化项目中，只新增 `sn-motion-html`，使现有 SenseNova 图片能力可以交付风格一致、随滚动推进的图片叙事网页。

用户已明确选择：**图片驱动网页为默认，保留视频入口，但不自动启用。**

2026-09-16 修订要求：优先使用 Agnes 的免费路径替代默认 Seedance，保留 Seedance 接口并允许其他视频模型。名称核对发现 Image 2.5 Flash 是图片模型，因此本方案按“替换视频模型”的意图，采用 **`agnes-video-2.5-flash` 作为可选视频流程的默认模型**；图片仍为 `sensenova-u1.5-lite`。这项 Image/Video 名称解释是本次方案采用的工作假设；如用户确认连图片默认也要改变，再单独调整图片 provider，不把图片模型写入视频配置。

完成后仓库包含六个 skill：现有的 `sn-image-base`、`sn-image-doctor`、`sn-infographic`、`sn-image-imitate`、`sn-image-resume`，以及新增的 `sn-motion-html`。

本轮只更新既有方案。后续实施按本方案逐阶段进行；当前没有复制官方 skill 或 Agnes 客户端、调用生成服务、创建示例网站、提交 Git commit 或推送远端。

### 1.1 核心交付标准

- 用户说“用 SenseNova 把这些图片做成滚动故事网页”时，可以使用已有图片直接制作。
- 用户需要新场景图时，复用本地 `sn-image-base`，不维护第二套 SenseNova 图片客户端。
- 默认产物为 HTML、CSS、JavaScript、章节 JSON、验收通过的图片和必要说明，可本地预览和后续编辑。
- 没有视频账号、视频密钥、FFmpeg 或 ffprobe，不影响图片网页的初始化、制作、校验和交付。
- 视频仅在用户明确要求时进入独立分支；图片模式不会请求视频接口，也不会尝试加载模板中的假视频地址。
- 视频默认选择 Agnes Video 2.5 Flash；Seedance 和其他已适配视频模型显式选择，无自动跨提供商回退。
- 保留官方的单一固定媒体舞台、章节导航、风格一致性和响应式布局；图片模式如实称为图片叙事，不宣称具有生成视频的连续镜头效果。

### 1.2 排除范围

不引入 PPT、数据分析、搜索、深度研究、团队协作、主动跟踪、更新器等其他 skill。不恢复官方整包配置、工作台、CI 或示例集合。不新增通用网站平台、后台、数据库、任务队列、前端框架或第三方图片提供商抽象。发布托管也不属于本次实施。

## 2. 已核实的基础与差异

以下结论来自当前项目、官方下载版和 Agnes 参考仓库的源码对比。2026-09-16 尝试读取 Agnes 官方图片/视频 Flash 文档，网页工具未取得正文，官方域名搜索也没有返回结果；没有执行生成调用。接口细节暂以参考源码和其 2026-09-12 核验记录为依据，免费额度、实时价格和账户可用性仍不能据此确认。

| 项目 | 当前情况 | 引入时的处理 |
|---|---|---|
| 官方 skill 文件 | `sn-motion-html` 目录共 30 个文件，包括 6 个 Python 脚本、6 份参考文档、模板、3 个视觉预设和宿主展示元数据 | 以该目录作为唯一新增 skill 来源，记录来源提交 |
| 图片生成 | 当前已支持 U1.5 Lite、原生编辑、多参考图、4K、Base64 落盘和受控回退 | 直接复用，默认模型与密钥规则不变 |
| Agnes 模型类型 | `agnes-image-2.5-flash` 是图片模型；`agnes-video-2.5-flash` 才是视频模型 | 两种能力分别配置，不能将 Image 模型 ID 发给视频接口 |
| Agnes CLI 默认值 | 参考仓库图片默认 2.5 Flash，但视频默认仍为 `agnes-video-v2.0` | 新 motion 流程显式传入选定的视频模型，不能依赖参考仓库的默认值 |
| Agnes 视频输入 | Flash 的 keyframe/reference 输入要求公开 HTTPS URL | 增加本地素材与临时 HTTPS 地址映射；不能直接复用 Ark 的 Data URL 输入 |
| Agnes 依赖 | 标准库 CLI，参考仓库要求 Python 3.10+ | 仅启用 Agnes 路径时检查，不抬高现有图片 skill 的最低解释器要求 |
| 官方工作流 | 完整流程以 Seedance 场景视频和连接视频为核心，图片主要承担静帧与回退 | 增加明确的图片默认路径，视频路径按需执行 |
| 运行路径 | 官方示例依赖当前工作目录和裸 Python 命令 | 统一绝对脚本路径、绝对项目路径和已验证解释器 |
| 仓库边界 | 范围脚本、完整性测试、环境检查、README/INSTALL 与 `docs/sn-image-generate*.md` 都写死五个 skill | 精确增加第六个，不放宽为任意 skill；本地指南的技能枚举同步改为六个 |
| 环境检查 | `check_environment.py` 维护独立的安装清单 | 增加新 skill；视频依赖按需诊断，不能成为全局要求 |
| 图片校验 | 官方 `verify_media.py` 先要求 ffprobe，再读取视频清单 | 先识别媒体模式；图片模式走 Pillow 与 JSON 校验 |
| Contact sheet | 官方脚本只抽取视频中间帧，依赖 FFmpeg | 图片模式直接读取章节静帧，复用现有 Pillow |
| 临时文件 | 官方在输出项目的 `tmp/` 写原始视频、抽帧、任务记录等 | 一次性文件进入系统临时目录；可恢复的任务状态单独保存 |
| 初始化 | 标题先替换进 JSON 字符串再解析，HTML 也是直接替换；`--force` 合并覆盖模板文件 | 先解析 JSON 再赋值，HTML 转义；明确覆盖范围并保护已有成果 |
| 浏览器运行层 | 已有海报回退；减少动态效果时仍计算图片缩放；动画循环销毁时未取消 | 将图片模式显式化，补齐减少动态效果和生命周期处理 |

当前五个图片 skill 的本地增强继续保留，包括图片校验、密钥发现、中文文本质量控制、事实保护、布局确认、候选排序和临时文件清理。现有 87 个布局、66 个风格定义不需要更新。

## 3. 总体设计

### 3.1 简单的职责分工

```text
用户需求 / 已有图片
        ↓
sn-motion-html：章节、风格、图片选择、网页编排与验收
        ├─ 已有图片：直接检查并使用
        ├─ 新图 / 改图：调用现有 sn-image-base CLI
        └─ 用户明确要求视频：进入统一视频编排入口
                     ├─ Agnes：Video 2.5 Flash
                     └─ Ark：保留 Seedance，可显式选其他已适配模型
        ↓
story.json + 静态网页 + 最终媒体
```

不新增总控服务或 SenseNova 图片客户端。宿主 Agent 负责理解需求、组织章节、判断图片一致性和发起 CLI 调用。图片生成与编辑继续使用现有运行层。视频流程用一个入口和 Agnes、Ark 两个小型适配模块，共享项目校验、状态恢复、下载和本地转码，不引入动态插件框架。

### 3.2 模式契约

拟新增一个项目字段：`meta.mediaMode`，仅允许 `images`、`video`。

| 行为 | `images`，新建项目默认 | `video`，显式选择 |
|---|---|---|
| 必需媒体 | 每章有效静帧 | 每章静帧、场景视频和相邻连接视频 |
| 交互 | 单舞台图片切换、克制的缩放或淡入淡出、完整章节文案 | 滚动映射视频进度，支持正向和反向拖动 |
| `clip` | 不要求；即使遗留字段存在，也不加载 | 必须校验 |
| `connectors` | 不要求；运行时忽略视频连接记录 | 默认要求章节数减一；明确接受切镜时可例外 |
| 校验工具 | Python、Pillow | 额外需要 FFmpeg、ffprobe |
| 服务凭证 | 只有生成新图时需要图片凭证 | 额外需要视频提供商凭证 |
| 缺失媒体 | 静帧缺失必须报告，不能把占位画面当最终交付 | 视频失败保留静帧，并明确报告降级 |

新建项目始终写出 `mediaMode`。读取没有该字段的官方旧项目时：有实际声明的 clip/connector 则按旧视频项目处理，否则按图片处理，并提示补写字段。未知值拒绝。显式 `images` 优先于遗留视频字段，避免误加载。

减少动态效果模式下停止图片缩放和视频加载，保留静态图片、可读文本和章节导航。图片模式与视频失败回退是两个不同状态，验收与交付说明必须区分。

## 4. 图片流程与本地运行层接入

### 4.1 触发与路由

- `sn-motion-html`：多张图片组成网页故事、滚动产品展示、图像时间线、沉浸式场景浏览。
- `sn-infographic`：单张信息图、海报、长图和数据视觉总结。
- `sn-image-imitate`：参考图片的风格或版式重设计。
- `sn-image-base`：基础生图、编辑和多图融合。
- 普通应用开发、后台、表单网站不因“网页”一词触发新 skill。

只在发现路由冲突时，对现有 skill 的描述补充短边界说明；不重写它们的工作流。

### 4.2 路径、解释器与配置

在新 skill 中定义逻辑路径 `MOTION_SKILL_DIR`、`PROJECT_ROOT`、`BASE_SKILL_DIR`、`RUNNER`、`PYTHON`，均先解析为绝对路径。它们是执行时解析结果，不要求用户设置额外环境变量。

沿用通过 `sn-image-doctor` 的解释器。PowerShell 使用调用运算符运行带空格的可执行文件路径；POSIX 使用带引号的绝对路径。命令不依赖 shell 曾激活虚拟环境。

图片凭证仍按现有 `SENSENOVA_API_KEY`、能力级覆盖和 `SN_ENV_FILE` 约定发现。由于脚本路径绝对化并不会改变 `.env` 的当前目录搜索规则，执行前须确认选中的环境文件；跨目录运行时可显式提供已有 `SN_ENV_FILE`，不要复制密钥来解决路径问题。视频分别读取 `AGNES_API_KEY` 或 `ARK_API_KEY`，不与图片密钥互相替代。Agnes 参考 CLI 只读进程环境，不自动加载 `.env`；项目私有环境文件由统一入口加载后，仅将所选 provider 的必要配置传给子进程。

### 4.3 制作步骤

1. 提取主题、受众、语言、设备、章节、已有图、参考图和事实要求。
2. 先提交完整且简短的章节与视觉方向方案。用户已明确给出的要求计入决策，不重复提问。需要确认的缺口集中呈现；官方的风格与内容两项决策可以在同一评审包中记录。
3. 已有图片满足要求时直接使用；需生图时，先做小规模一致性验证。通常最多取开头、中间、结尾三张，短故事不额外凑足三张。
4. 获得必要的方向确认后完成静帧集。角色、产品和关键物体跨图复用身份描述，优先采用原生编辑和相关参考图维持一致性。
5. 图片提示词只负责画面，正文、按钮、来源等交给 HTML，减少中文文字进入像素后难以修改的问题。
6. 使用现有 CLI 的 `--prompt-path` 读取临时 UTF-8 提示词。图片统一记录原始输出、采用模型、是否回退和选用结果。
7. 验收通过的图片进入交付项目；原图与网页压缩图分开，压缩不能覆盖原图。执行图片校验、contact sheet 和浏览器检查。
8. 交付项目及预览地址，说明实际媒体模式、图片检查结果和未解决项。

批量生成前列明新增图片数量和修正次数。已有用户预算优先；无明确批量预算时先完成小样，不自行扩成大量候选。复用运行层的瞬时错误重试，不再叠加一层隐式重试倍增调用。实际模型回退后必须重新检查风格一致性。

### 4.4 项目文件与临时文件

最终项目包含：网页源码、`content/story.json`、接受的场景图/参考图、网页海报、最终视觉设定和必要使用说明。可编辑故事 JSON 是产品本身，不能当作临时分析 JSON 清理。

组装后的提示词、分析草稿、失败候选、原始转码输入、临时抽帧进入系统临时目录下的独立任务目录；交付后清理。用户明确要求可复现素材时，保留经过筛选的最终创作说明，而不是全部请求日志。

视频恢复所需的任务 ID 与状态是例外：保存在项目私有、忽略版本控制的状态目录，直到任务完成；不随一次性临时目录清理。公共预览和发布目录不得暴露该状态。

## 6. 必须完成的实现优化

### 6.1 图片模式与输入一致性

- 校验至少一个章节、唯一安全 ID、有限正数 span、有效图片路径及允许的枚举值。不能让空 chapters 导致浏览器启动后访问空段落。
- 图片项目不要求 video manifest、不探测 ffprobe、不请求 MP4；网络面板与 CLI 测试都要证明这一点。
- 普通项目媒体路径使用项目内相对路径，拒绝绝对路径、盘符路径和 `..` 越界；解析符号链接后的路径也必须在允许目录内。用户外部图片作为输入时先明确导入为项目资产，避免交付结果依赖用户机器的绝对路径。
- 初始化先解析模板 JSON，再赋值标题等字段，避免引号、反斜杠和换行破坏 JSON；写 HTML 时正确转义文本和属性。
- 初始化遇到非空目录默认停止；保留 `--force` 时明确哪些模板文件会覆盖，并避免覆盖最终图片、用户配置和状态。无需实现复杂合并器。

### 6.2 可读性、可访问性和运行性能

- 中文为项目语言选项之一，`html.lang`、来源按钮、章节导航和加载提示同步变化，内容默认跟随用户语言。
- 窄屏不以缩小字体来容纳无限文案；约束章节密度或提供当前章节可滚动的阅读区域，并保证键盘可达。
- 不活动章节除了透明度，还需正确处理辅助技术和焦点可达性，防止读屏器一次读出全部叠层内容。
- 图片模式只在滚动/状态变化时更新画面，不持续运行视频 seek 循环。页面隐藏或卸载时取消动画、事件与未完成请求。
- 视频模式保留邻近加载，释放离开活动窗口的 Blob URL；处理媒体解码错误和销毁后的异步回调。
- 来源链接只接受明确允许的协议；内容仍通过文本节点或转义输出，不能执行 story JSON 中的脚本。

### 6.3 本地预览与交付边界

官方服务脚本已有隐藏路径拒绝逻辑，但默认目录浏览和符号链接暴露边界仍需验证。优先提供只服务网页所需文件的简单规则：HTML、CSS、JS、content 与正式媒体，拒绝配置、提示词、私有状态和临时材料；不能仅依赖文件名以点开头。

交付源码项目和可公开发布的网页文件集要有清楚说明。当前先完成本地预览，不实现自动部署或上传。用 HTTP 预览读取 JSON 的网页，不声称双击 file:// 一定可用。

## 7. 默认 Agnes、保留 Seedance 的视频接入方案

视频仍为显式启用的可选能力。用户的视频替代目标对应 `Agnes Video 2.5 Flash`；`Agnes Image 2.5 Flash` 只能产出静帧，不能替代 Seedance 产出视频。图片模式实现完成后再接通视频路径，不将默认视频模型的变化解释为自动开启视频。

### 7.1 启用条件

必须有明确的视频需求、视频模式项目和通过校验的清单。新项目的视频候选默认配置为 provider=`agnes`、model=`agnes-video-2.5-flash`；Seedance 作为显式 Ark 选项保留。用户已授权某批生成时，沿用该授权，无需每个片段重复确认；编写方案或初始化项目本身不触发生成。

“免费”按用户当前使用前提记录，执行策略为 `costPolicy=free-only`、自动付费回退关闭；这不是对公开 API 永久免费的承诺，也不能仅凭网站 UI 免费推定 API 免费。离线 plan 同时输出已知费用依据或 `cost_verified=false`。首次实际执行前只核实一次当时账户适用的额度/计费范围；证据不足则保留可审阅的计划，不自动改用 Seedance、Agnes Video 2.0 或付费模型。用户明确接受新的计费范围后再执行对应请求。

免费也不代表无限量：记录计划片段数、允许重试数和并发上限。默认并发建议 1，经实际账户限额验证后允许配置提高；不能沿用官方 Seedance 示例中的四并发来推断 Agnes 免费配额。

无视频凭证时仍可阅读指南、检查清单和运行离线 plan；不自动索取或创建账号，不阻塞已完成的图片网页交付。

### 7.2 能力与接口差异

| 项目 | Agnes Video 2.5 Flash，拟默认 | Ark / Seedance，保留 |
|---|---|---|
| 提交入口 | `POST https://api.agnes-ai.cn/v1/videos` | `POST {ARK_BASE_URL}/contents/generations/tasks` |
| 查询入口 | 域名根路径 `/agnesapi?video_id=...&model_name=...`，不在 `/v1` 下 | `/contents/generations/tasks/{id}` |
| 成功终态 | 参考客户端识别 `completed` | 官方下载版识别 `succeeded` |
| 帧输入 | 公开 HTTPS；不接受本地路径或 Data URI | 原实现将本地帧编码为 Data URL |
| 模式 | `text`、`keyframe`、`reference` | 由具体模型支持的 conditioning 方式决定 |
| 生成时长 | 4–12 秒整数，提交为字符串字段 `seconds` | 依据选定模型验证，不共用 Flash 上限 |
| 分辨率 | 请求字段 `size=720P` | 依据选定模型验证 |
| 比例 | 21:9、16:9、4:3、1:1、3:4、9:16 | 依据选定模型验证 |
| 参考图片 | reference 最多 5 张；与 keyframe 输入不能混用 | 依据模型与原适配器验证 |
| 参数差异 | 不发送 frame_rate、negative_prompt、num_inference_steps 或任意 extra_body | 不把 Agnes 的 seconds/size 直接透传给 Ark |
| 声音 | 参考资料说明模型可能合成音轨；没有已核实的无音频请求开关 | 原适配器包含 generate_audio 参数 |

Agnes 请求示意：`model`、`prompt`、`seconds`、`mode`、`size`、`aspect_ratio`、`n=1`，按模式增加 `first_frame` / `last_frame` 或 `images`。引用图片时提示词中的 `<Picture N>` 保持输入顺序。首期不接参考音频、TTS 和自动字幕，避免为图片网页新增另一套音频工作流。

网页默认静音通过本地 FFmpeg 移除原音轨实现；不能向 Agnes 发送未经确认的 `generate_audio=false`。也不能把默认网页 24fps 当作 Flash 接口的 frame_rate：它是下载后的标准化目标。

### 7.3 项目配置与其他模型

继续使用 `prompts/video-manifest.json`，在现有字段上增加 `provider` 和 `costPolicy`；保留顶层 `model`、`duration` 等已有字段，不再新增一套平行模型配置。新建图片项目无需实际创建该清单；请求升级到视频时生成以下默认项：

```json
{
  "provider": "agnes",
  "model": "agnes-video-2.5-flash",
  "costPolicy": "free-only",
  "duration": 4,
  "resolution": "720p",
  "ratio": "16:9",
  "conditioning_mode": "first_last",
  "generate_audio": false,
  "target_width": 1280,
  "target_height": 720,
  "fps": 24,
  "dives": [],
  "connectors": []
}
```

这是默认字段示意，不是可直接提交的成品清单；实际执行必须有与章节一致的片段。`generate_audio` 表示交付音频策略，由 provider 决定是否能在请求端表达；Agnes 在本地转码处理。

- 选择优先级：当前明确 CLI 覆盖 > 项目清单 > 所选 provider 的模型环境变量 > 内置默认。新项目显式写出 Agnes Flash，旧的 AGNES_VIDEO_MODEL 不覆盖已保存的项目选择；省略 model 的项目才使用环境后备值。解析后始终把实际 model 传给 Agnes CLI。
- 凭证与 base URL 绑定 provider：Agnes 读取 `AGNES_API_KEY` / `AGNES_BASE_URL`；Ark 读取 `ARK_API_KEY` / `ARK_BASE_URL`。不混用 key，不在静态网页中保存任何一方配置。
- provider 和 model 必须成对验证。切换到 Ark 时显式指定该服务商已验证的模型 ID；不把 Agnes 默认 ID 带入 Ark，也不复制未经核实的旧 Seedance 示例 ID 作为当前默认。
- 旧 Seedance 清单缺少 provider 时，只有已识别的旧模型命名或旧兼容命令才判定为 Ark；识别不出的清单要求补写 provider。兼容入口与新默认不可互相污染。
- 首期提供 Agnes Flash 和 Ark 两种协议路径。其他同协议视频模型通过明确的能力记录接入，包含模式、时长、尺寸、URL/内联输入、轮询方式及终态；至少有一组请求/响应契约测试。不同协议增加小适配文件，不把“允许其它模型”实现成把任意模型名套入 Flash 或 Video 2.0 请求。
- 未适配模型在网络前报告 unsupported_model；不能悄悄切换。图片模型 ID 出现在视频 model 中时给出专门提示。
- 恢复状态保存 provider、非秘密 endpoint 标识、model、task_id 和请求摘要。恢复操作使用原配置，不受用户后来切换默认模型影响；修改配置意味着新的显式任务。

### 7.4 Agnes 素材 HTTPS 桥接

这是本次替换的必要条件，不能只改 model 字符串。Agnes 参考仓库没有素材上传命令，其 HTTPS 检查仅验证 scheme/netloc，不能证明远端可访问或拒绝私网地址。

首期采用明确的媒体 URL 映射文件，放在项目私有状态目录，键为项目内路径、值为仅含最终图片内容的 HTTPS URL；可包含内容摘要与失效时间。优先复用用户已提供、允许用于此次生成的公开素材地址。生成服务返回的临时图片地址也必须在任务期内有效；不要把签名 URL 写入公开 story JSON、日志或文档。

本地图片没有可用 URL 时，离线 plan 报告具体缺失项 `media_url_required`，图片网页仍可交付。批量执行前需要用户提供 URL，或使用其已授权的媒体存储完成上传；本方案不指定未经选择的免费图床，不自动公开本地素材，也不把整个项目目录暴露成公网服务。媒体临时上传与网站发布是两个动作。

为保持原连续镜头流程，分两阶段：

1. 场景静帧具备 URL 后，以 Agnes keyframe 的 first_frame 生成场景视频；reference 只在需要身份参考时显式选择。
2. 下载、标准化场景视频并抽取真实末帧/首帧，为这些新生成的边界帧建立 HTTPS 映射，再提交 keyframe 连接片段。

仅给原场景图配置一次 URL 不足以完成第二阶段。缺少已授权上传渠道时，执行停在边界帧待映射处，保留已完成场景和任务状态；不会重生成场景，不改用 text 模式冒充首尾帧连续。显式接受切镜时才能省略连接视频。

URL 在提交前检查协议、禁止本机/私网/用户凭证 URL，并对实际下载设置重定向和大小边界。任何在线可访问性探测都与离线 plan 分开；不要以一次 HEAD 成功承诺供应商必定能访问。素材有效期覆盖排队、生成和必要恢复，完成后按用户存储约定删除临时上传副本。

### 7.5 源码复用和适配边界

定向复制参考仓库的标准库 CLI 到新 skill 的 vendor 目录，保留许可证和来源 SHA；不导入其 SKILL.md，不修改外部 Agnes 仓库，不把该 D 盘路径硬编码进交付项目。轻量适配层通过参数数组调用 CLI 并读取单个 JSON，避免 shell 拼接。Agnes 原 CLI 没有 `--prompt-path`：统一入口读取 UTF-8 文件后，以 subprocess 参数列表传入 `--prompt`，不能伪造上游不存在的参数。

Agnes 使用分离的 video-submit、video-status/video-wait；提交返回 ID 后立即保存，后续显式携带 model 查询，避免退回参考仓库的 Video 2.0 默认。原 CLI 的 `ok=true` 不代表已成功落盘：download_error 或缺少有效 local_path 都是未完成。适配层根据状态与本地媒体校验决定完成，而不是只看退出码。

原下载器一次读取整个响应并直接写文件，不能直接作为长视频最终落盘路径。首期通过 `--no-download` 获取成功任务的结果位置，由共用的有界流式下载、临时文件和原子替换流程接手；剔除原响应/异常中的签名 URL 后再记录错误。轮询使用总墙钟截止时间、单请求超时和有限退避，不把“最大循环次数”当作严格超时。

### 7.6 两个提供商共用的恢复与校验

官方脚本目前在“创建任务、轮询、下载、转码”的整个循环上重试，因此轮询或本地转码失败可能重新创建计费任务；仅凭输出非空就跳过，也不能证明文件完整。

实施时必须：

1. 创建成功后立即保存任务 ID；后续轮询恢复同一个 ID。
2. 创建请求结果不确定时报告状态，避免自动重发产生重复任务。
3. 下载失败重试下载，转码失败只重做本地转码；两者不再次生成视频。
4. 保存部分下载和转码到临时文件，完整验证通过后再原子替换正式输出。
5. 恢复跳过依据是媒体验证通过，而不是文件长度大于零。
6. 权限、认证、计费、模型未开通和参数错误不可盲目重试；同时判断 HTTP 状态和结构化错误码。
7. 在任何 POST 前检查片段 ID、引用关系、文件、时长、数量和路径；`plan` 不能只是打印计数。
8. 状态只存必要脱敏字段，不持久化完整响应、带签名下载地址或 Base64；原始素材缓存仍放系统临时目录。

保持场景视频先完成、从实际视频抽取边界帧、连接视频后执行的依赖顺序。只使用现有有界执行方式，不建设队列或守护进程。

### 8.1 P3（视频路径）冻结

2026-09-16 决定冻结 P3a 与 P3b，本轮不实施视频路径。

依据是实测结论而非偏好。图片模式已完成三视口浏览器验收，用户提供的素材在零生成调用、零视频凭证、零站外请求的条件下跑通全流程（§12.2 与 §12.3）。视频路径要换取的是“连接片段所发明的中间空间”和“场景内的真实主体动作”——这两项确实无法由网页技术替代，但代价包含四项独立前提：视频服务凭证、按量计费授权、FFmpeg/ffprobe 依赖，以及 §7.4 要求的**公网可达 HTTPS 素材渠道**。最后一项比费用更硬：本地图片没有可公开访问的 URL 时，执行会停在边界帧待映射处。

冻结而非删除。设计已经完成，删除会在未来需要时重做；冻结则保留为显式可选入口，且不占用当前实施精力。方案本身对视频的定位（默认不启用、需显式授权）没有改变，因此图片模式作为产品主线不需要改写方向。

冻结带来的直接后果与处置：

1. `references/agnes-video.md`、`references/video-providers.md`、`scripts/video_pipeline.py`、`scripts/agnes_adapter.py`、`scripts/ark_adapter.py`、`scripts/vendor/*`、`tests/test_video_pipeline.py` 均不创建（§12.4 已记录）。
2. `references/seedance.md` 与 `scripts/seedance_pipeline.py` 保持官方原样。因此 §7.6 指出的“轮询或转码失败会在整圈重试中重新创建计费任务”问题**随冻结搁置**——不执行视频路径就不存在该风险。这是冻结的收益而非遗漏，但必须在解除冻结时优先修掉。
3. `content/story.json` 的 `mediaMode: "video"` 目前仍可写出，但没有可用的生成入口。视频模式项目只能做离线清单校验，不能产出片段；`verify_media.py` 会如实在缺少 ffprobe 或片段时报告。
4. `?motion=full` 审阅开关、`meta.crossfade`、`meta.drift` 均为图片模式能力，与冻结无关。

解除冻结的条件是三项同时具备：明确的视频需求、已授权的素材上传渠道、以及覆盖模型与批次范围的计费授权。缺任何一项，只做离线 plan，不发起请求。
