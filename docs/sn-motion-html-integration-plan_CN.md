## 1. 当前决策

**第一阶段交付一套不需要视频接口、能直接产出可看网页的图片视觉叙事工具。**

用户最新决定是先做好图文故事页、分镜稿和海报，完成后再考虑视频接入。本方案据此替代先前以 Agnes/Seedance 默认模型、素材上传和视频适配器为中心的实施安排。

“无视频配置”是完整且受支持的产品形态。用户不用配置 Seedance、Agnes 视频、FFmpeg、ffprobe、公网图床或视频计费账户，也能完成第一阶段全部成果。图片的缩放、淡化和滚动叙事来自浏览器；不承诺人物真实动作、物体运动或生成式连续镜头。

### 1.1 第一阶段的三种成果

| 成果 | 用户拿到什么 | 何时算完成 |
|---|---|---|
| 图文故事网页，默认 | 可本地打开预览、具有真实图片和完整文案的响应式故事项目 | HTTP 预览可看；章节、导航、正反滚动、移动端阅读均正常 |
| 分镜稿 | 按顺序排列的场景图、镜号、文案与镜头意图；可编辑 Markdown 和可阅读的静态 HTML | 不依赖正在滚动的网页状态，能一次审阅完整故事顺序 |
| 展示海报，按需 | 从故事提炼的主题、主视觉和少量重点信息组成的独立图片 | 有明确尺寸、可读文字和最终文件；不是单纯把 PNG 转成 WebP |

默认先交付网页；需要分镜或海报时，复用同一套故事内容和已验收图片。用户要求多个成果则一并交付，不为没有请求的成果额外生图或增加导出流程。

### 1.2 第一阶段范围

- 只在现有六个 skill 范围内完善 sn-motion-html，不再新增第七个 skill。
- 已有图片优先直接使用，允许零模型调用。
- 需要新图片或修图时，复用 sn-image-base 和当前 SenseNova 图片默认配置。
- 图文故事、产品演变、历史时间线、旅行叙事、视觉讲解和概念分镜是主要用途。
- 分镜与故事海报围绕同一叙事复用内容；独立海报仍路由现有 sn-infographic。
- 网页制作不新增前端框架、后台、数据库、任务队列或在线编辑平台。

## 3. 第一阶段的产品流程

~~~text
主题 / 原始文案 / 已有图片
        ↓
故事结构：受众、主线、章节、每章关键信息
        ↓
分镜：场景顺序、构图、画面说明、阅读文案
        ↓
选用已有图 / SenseNova 生图与编辑 / 一致性检查
        ↓
同一份故事数据与已验收图片
        ├─ 图文故事网页
        ├─ 分镜 Markdown + 分镜 HTML
        └─ 按需调用 sn-infographic 生成故事海报
~~~

### 3.1 先保证叙事能读懂

每章只承载一个主导事件或信息点。先确定起点、变化、结果和章节间的因果或时间关系，再决定风格、图片和转场。

图片与文字要互相补充：图片表达场景、氛围、主体和空间；HTML 保留标题、事实、正文与来源。不要把全部中文正文烧进图片，也不要让效果掩盖故事逻辑。

已有完整内容与图片时，可直接编排初稿。用户已经明确的风格、章节与用途无需重复确认；只有会显著改变内容或生成数量的缺口需要集中提问。

### 3.2 缺少素材时的行为

- 有真实图片：先导入项目并检查顺序、尺寸、质量和使用范围。
- 只有故事内容：先完成分镜；调用已有图片能力完成静帧后再交付最终网页。
- 暂时无法生成图片：可以交付明确标记为“待配图”的分镜草稿，不能把占位模板称为完整视觉成品。
- 有少量可用图：先用可用图制作最小完整故事，不自动扩写更多章节来填充模板。
- 已批准的任务可直接按其生成范围执行；不要因为“分镜”新增逐张审批流程。

### 3.3 图片一致性

需要生成新图时，以同一视觉风格块和角色/产品身份描述控制一致性。短故事可以先验证一个代表场景；较长故事最多取开头、中间、结尾作为小样，不机械凑图数。

优先使用原生图片编辑和相关参考图维持身份。每次选用结果要检查主体、事实、文字、水印、构图及移动端裁切。生图失败和质量不合格分开记录，沿用现有重试与预算规则。

## 4. 一份数据服务网页和分镜

继续以 content/story.json 作为唯一叙事内容源，不另建第二套 story 数据或工作流状态机。

### 4.1 沿用已有字段

- meta：标题、简介、语言、风格、界面、mediaMode=images、淡化和缩放参数。
- chapters：稳定 ID、短导航标签、标题、正文、静帧路径、文案位置和阅读跨度。
- sources：事实内容的来源说明。

正式项目只声明真实存在的静帧，不要求 clip、connectors 或 video-manifest。遗留视频字段在显式 images 模式下不加载。

### 4.2 分镜的最小补充字段

如现有章节字段不足以表达分镜，只新增一个可选 shot 对象：

| 字段 | 用途 | 约束 |
|---|---|---|
| intent | 这一镜要讲清什么 | 简短，不复制整段正文 |
| framing | 景别、角度、主体位置和留白 | 描述当前静帧 |
| motionNote | 将来拍摄或动画的运动意图 | 仅说明，不触发视频生成，不声称已经实现 |

镜号由章节顺序生成；稳定身份仍使用章节 ID。网页可以忽略 shot，旧项目不用补字段也能浏览。span 始终代表阅读/滚动距离，不改成视频秒数。暂不增加视频提供商、帧率、任务 ID 或生成时长字段。

分镜 Markdown/HTML 从 story.json 生成：修改内容后重新导出，避免维护几份互相漂移的正文。交付说明须标出后续编辑的主入口。

## 5. 三类成果的具体实现

### 5.1 图文故事网页：第一优先级

保留现有固定图片舞台、章节导航、克制缩放和交叉淡化，优先打磨以下细节：

1. 首屏能看清主题和主视觉，正文不会与导航或主体冲突。
2. 正向与反向滚动、点击跳章都显示正确图片和完整文案。
3. 手机上不靠无限缩小字体塞内容；正文可读，需要时在当前章节内滚动。
4. 减少动态效果时停止缩放，仍有静态图片、文本和导航。
5. 明确区分图片缺失、图片加载中与正常状态，不以默认占位画面掩盖错误。
6. 只访问项目本地图片和网页文件；预览不产生视频 API 或 MP4 请求。

现有 crossfade、drift 和审阅开关继续保留。每次只因具体可读性或构图问题调参，不增加大量动效预设。

### 5.2 分镜稿：第二优先级

在新 skill 内增加一个小型分镜导出脚本，拟命名 scripts/export_storyboard.py：

- 输入项目根目录，读取现有 story.json，复用 project_model.py 校验。
- 输出 exports/storyboard.md 和 exports/storyboard.html。
- 每镜包含编号、标题、场景静帧、正文、构图与镜头意图；没有可选说明时省略对应区域。
- HTML 采用普通文档流与网格，自适应显示整套分镜；不依赖故事页的滚动舞台。
- 使用真实相对媒体路径；Markdown 与 HTML 显示相同顺序和正文。
- HTML 含适合浏览器打印的样式；第一阶段不强制生成 PDF，也不新增打印服务。
- 联系表仍用于选图与质量检查；需要图片版分镜总览时再复用 Pillow 输出，不复制两套拼图逻辑。

静态 HTML 本身就是“可看的网页”，用户仅需要分镜稿时，不必被迫制作滚动故事页。

### 5.3 展示海报：第三优先级

先分清用户要的成果：

- 网页压缩图：继续使用 make_posters.py，输出对应场景的 WebP，不增加版式功能。
- 故事展示海报：提炼标题、主视觉、核心信息与尺寸，调用现有 sn-infographic，复用当前确认、质量审查和文字纠错规则。
- 分镜总览长图：使用分镜导出/联系表能力，保持每镜顺序与标签，不当作营销海报。

故事海报的简报直接取自已确认内容，不编造新的事实。精确中文长正文优先保留在网页和分镜中；海报只用适量必要文字。

第一阶段不承诺“网页任意位置一键截成完美海报”。若用户要像素级文字准确、可复现的 HTML 排版海报，后续按具体需求扩展固定尺寸导出，不提前引入整套浏览器自动化运行依赖。

## 7. 本地运行与产物规则

### 7.1 依赖

已有图片 → 网页/分镜，只需通过诊断的 Python、Pillow 和浏览器。新图片/故事海报生成另需现有 SenseNova 凭证。无需 Agnes、ARK 凭证和视频媒体工具。

所有示例解析绝对项目路径、绝对脚本路径和已验证解释器。遵循当前 .env 与 SN_ENV_FILE 规则；不为了运行新工具复制或打印密钥。

### 7.2 项目交付

~~~text
index.html
styles.css
src/
content/story.json
assets/images/scenes/
scripts/
exports/
  storyboard.md       按需生成
  storyboard.html     按需生成
  story-poster.png    按需生成；名称可随任务调整
~~~

网页、图片、正式分镜和海报是用户成果，保留在输出项目。组装提示词、分析草稿、失败候选和内部评审联系表放系统临时目录，结束后按现有约定清理。

Markdown/HTML 分镜引用项目媒体，交付时附完整项目，而不是单独发送一个依赖本机路径的文件。浏览器读取 story.json 的故事页通过 HTTP 预览。静态分镜 HTML 应尽可能在无服务状态下仍可阅读本地相对图片，不额外依赖 fetch。

### 7.3 预览边界

沿用当前本地服务白名单，不暴露凭证、提示词、状态、系统临时目录或目录列表。正式分镜 HTML 如需纳入服务，增加精确规则；HTML 内容和 URL 继续做必要转义与路径检查。

网站部署不在当前目标中。本地项目能交付、能预览即可，不要求图床或公网存储。

## 9. 第一阶段验收

### 9.1 自动检查

- 现有图片运行层和 motion 测试继续通过，范围检查仍为六个 skill。
- 图片项目不生成视频凭证、视频目录和视频清单，不探测 FFmpeg/ffprobe。
- 分镜输出与章节顺序、ID、标题、正文一致；可选 shot 缺失时也能导出。
- 中文、引号、换行、HTML 特殊字符正确输出；图片引用可解析且不能越出项目。
- 缺图、损坏图、无效 JSON、空章节明确失败，不能使用 allow-missing 为最终成品验收放行。
- 预览只允许正式页面与媒体，新增导出路径不会暴露其他文件。

### 13.3 真实故事验收中发现并修正的缺陷

以 §12.3 的三章节中文演示项目（`sn-motion-demo`）实测，三张 1800×1016 真实静帧，全程零生成调用。以下缺陷均在本次浏览器验收中发现，均已修复并补回归测试：

| 缺陷 | 现象与根因 | 修复 |
|---|---|---|
| `?motion=full` 审阅开关对缩放无效 | 运行时按开关正确写入了 `scale(1.0722)` 内联样式，但样式表里 `@media (prefers-reduced-motion: reduce) { transform: none !important }` 优先级更高，把它覆盖了。本机系统动画为关闭（§12.1 已记录），因此审阅者恰好无法验证缩放——即该开关存在的原因失效 | 由运行时把解析后的结果写到 `<html data-motion>`，样式表改为 `:root[data-motion="reduce"]`，媒体查询不再参与，CSS 与 JS 共用同一个决定 |
| 点击章节跳转后没有文案 | 跳转目标是场景段的起点，而文案在自己的段内前段淡入，落到边界时上一章文案已淡出、本章文案尚未出现，只看到图片 | 在 `layout()` 中计算文案稳定的位置 `copySettled`，跳转用它作为目标；文案淡入窗口与跳转目标共用同一个值，不会各自漂移 |
| 手机正文被压到 12.5px | 移动端 `clamp(.76rem, 3.2vw, .88rem)` 在 390px 宽下算出 12.48px，属于“缩小字体塞内容” | 改为 `clamp(.9rem, 3.9vw, 1rem)`：390px 下 15.2px，320px 下保底 14.4px；超出面板高度时按既有设计在面板内滚动 |

| 时长 | 帧对齐 `8n+1`，上限 441 帧（24fps 约 18 秒） | 整秒 4–12 |
| 单张起始图 | `--mode ti2vid --image URL` | `--mode keyframe --first-frame URL` |
| 首尾两帧 | `--mode keyframes --extra-body '{"image":[A,B]}'` | `--mode keyframe --first-frame A --last-frame B` |
| 参考图/音频 | 不支持 | `--mode reference`，最多 5 张 |
| 其它参数 | 支持 `--frame-rate`、`--negative-prompt`、`--num-inference-steps`、`--extra-body` | 均不支持 |

两种模型都不接受本地素材，仍必须是公网 HTTPS URL，因此 §14 的锚定方式设计完全沿用：`generate`/`reference`/`url`/`text` 都不变，只是**同一意图在不同模型上翻译成不同参数**。转换集中在一个函数里（`video_args()`），清单不写模型专属字段。

值得记录的一点：连字符的「双锚定图」在 v2.0 上恰好表达为 `keyframes` 的首尾两帧，比 Flash 的 reference 模式更精确——它把接缝两端真正钉住，而不仅仅是引导。

## 18. 架构纠正：图片一律 SenseNova，Agnes 只做视频（2026-09-17）

用户指出：对用户而言根本不存在「Agnes 图片处理模块」，Agnes 相关模型只应处理视频。此前视频路径的锚定图走了 Agnes 的图片模型（`agnes-image-2.5-flash`），属于偏离，现已改正。

### 18.1 关键前提验证：SenseNova 的图片地址是公网可取

视频模型接受不了本地文件，所以「图片由 SenseNova 生成」要成立，就必须能从 SenseNova 拿到一个公网地址。实测（真实调用 + 无鉴权抓取）：
