## 现状与问题

- `sn-image-base` 保存图像时使用的原子写入 `.tmp` 文件，成功后被替换，异常时被删除。真实生成和编辑调用均未留下这种文件。

- 底层运行器在省略 `--save-path` 时，默认把生成的图像留在系统临时目录的 `sensenova-image` 下。该图像可能是最终交付物，不能仅凭目录位置就自动删除。

## 清理规则

| 文件 | 何时删除 | 说明 |
| --- | --- | --- |
| 图像写入用的 `.tmp` | 单次保存成功或失败时 | 保留现有逻辑。 |
| 提示词、分析 JSON、修正提示词、未选中候选图 | 技能任务结束时 | 成功和失败都要执行；多轮生成期间不能提前删除仍需引用的文件。 |
| 最终选中的图像 | 先发布到正式输出目录，再删除临时副本 | 用户可继续打开回复中的本地图片链接；正式输出不是临时文件。 |
| 用户提供的参考图、提示词文件及显式 `--save-path` | 不由清理程序删除 | 即使路径位于系统临时目录，也不推断它属于本次任务。 |

这里的“一次调用”指一次完整的技能任务。单次图像接口请求结束时，只能清理自身的 `.tmp`；多轮编辑可能还需要前一轮图像和分析文件。

## 建议实现

1. 在 `sn-image-base/scripts/` 增加一个任务文件管理入口，提供 `begin`、`publish`、`abort`、`gc` 四个命令。其他三个技能共用它，不分别编写删除逻辑。
2. `begin` 在系统临时目录下创建唯一的 `sensenova-tasks/<随机任务 ID>`，写入包含格式版本、创建时间和任务 ID 的归属标记，返回绝对路径。创建采用“先在临时名目录写入归属标记、再原子改名”的方式，使标记与目录同生，消除“已建目录、未写标记”的中间态。只允许后续清理这个入口创建并带有效标记的目录。信息图的任务目录应在用户确认视觉方向之后创建，避免确认等待期间积累目录。
3. 技能把自己的分析、提示词和候选图写入该任务目录。调用现有 `sn_agent_runner.py` 时继续显式传入 `--prompt-path` 和 `--save-path`，图像生成行为与模型选择不变。
4. 成功或存在可交付候选图时调用 `publish <任务目录> <选中图> [--final-path <目标>]`：验证选中图位于任务目录且是可读取图像；复制到目标目录中的临时文件、校验并原子替换为正式文件；确认正式文件存在后，删除整个任务目录；返回正式路径供 Agent 交付。发布失败时保留任务目录与原图，允许重试。
5. 无可交付图像、用户取消或任务失败时调用 `abort <任务目录>`，删除整个任务目录。各技能的失败处理步骤必须调用它；正常路径必须调用 `publish`。删除失败时返回明确错误，不能把残留报告为已清理。
6. `begin` 先执行一次 `gc`：只扫描 `sensenova-tasks` 下超过 48 小时且未被当前调用持有的目录，覆盖两类——带有效归属标记但已超期的目录，以及归属标记无效或缺失的目录（覆盖标记写入中断的半成品与外来残留）。用操作系统文件锁或等效独占标记保护正在运行的任务；清理前再次检查路径仍位于专用根目录内，拒绝符号链接、目录联接、重解析点和越界路径。`gc` 可单独运行，但不安装后台服务或计划任务。若此后再无调用，异常中断的目录会保留到下一次运行 `begin` 或 `gc`。
7. 直接调用 `sn_agent_runner.py` 且未给 `--save-path` 时，将默认输出改为正式输出目录，而不是系统临时目录。建议默认 `~/Pictures/SenseNova`，可由 `SN_IMAGE_OUTPUT_DIR` 覆盖；保留显式 `--save-path` 的现有含义。同步调整三种图像后端、文档和相关测试，避免只有某个后端继续写临时目录。
8. 技能文档里的 Python 命令统一禁用字节码写入，避免在技能脚本目录不断新增 `__pycache__`；既有缓存不由任务清理程序处理。

正式输出目录中的图片是交付物，不做静默过期删除。若用户明确指定目标路径，使用该路径；否则使用正式输出目录中的唯一文件名。技能文档中“未要求保留时删除最终图”的表述应改为“交付后仅删除任务临时目录”，因为本地图片链接仍依赖正式文件。

## 安全边界

- 只删除有本工具归属标记的专用任务目录；不扫描或清空整个系统临时目录，也不按文件名通配删除。
- `publish` 不删除用户传入的参考图或任意外部文件；最终目标必须位于任务目录之外。
- `publish` 必须先完成正式文件的原子写入，再删除临时目录，避免交付物丢失。
- 多任务并行使用不同随机任务 ID；一个任务的完成或回收不得碰触其他任务。
- 密钥仍通过环境变量读取，不写入归属标记、日志或临时文件。

## 验收方式

1. 使用真实密钥完成一次生成、一次基于前一轮图像的编辑，调用 `publish` 后确认正式图像可打开，任务目录及全部提示词、JSON、候选图均不存在。
2. 模拟接口失败、保存失败和发布目标不可写：分别确认 `abort` 可清理前两者，发布失败保留原图且可重试，没有半成品正式文件。
3. 模拟进程异常退出后调用 `gc`，确认仅回收超过 48 小时的本工具任务目录；近期任务、并行活动任务、无归属标记目录、链接和用户指定路径均不受影响。
4. 验证省略 `--save-path` 时三个后端都输出到正式目录；显式 `--save-path` 仍按原路径保存。
5. 复查 `sn-infographic`、`sn-image-imitate`、`sn-image-resume` 的成功、低质量但可交付、失败和取消路径，确保最终都调用 `publish` 或 `abort`。

## 审核决策（2026-09-23 已采纳）

- 默认正式输出目录使用 `~/Pictures/SenseNova`，可由 `SN_IMAGE_OUTPUT_DIR` 覆盖。
- 异常任务目录的回收阈值使用 48 小时。
- 两项为绑定决策：`publish` 未给 `--final-path` 时的默认目标即上述正式输出目录；若未来推翻正式输出目录决策，`publish` 默认目标需随之重新定义。
- 其他设计不依赖具体取值。实施时需同步落实本次审核新增的两条规则：`begin` 采用“临时名写标记后原子改名”创建，`gc` 增加“归属标记无效或缺失、超 48 小时”目录的回收。
