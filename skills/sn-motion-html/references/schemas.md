# Project schemas

## `content/story.json`

```json
{
  "meta": {
    "title": "Story title",
    "kicker": "Optional short genre or series label",
    "subtitle": "Short deck",
    "description": "Search and share description",
    "note": "Optional adaptation note",
    "style": "anime | cinematic | cgi",
    "ui": "folio | caption | graphic",
    "mediaMode": "images | video",
    "lang": "zh | en",
    "crossfade": 0.8,
    "drift": 0.16,
    "connectorSpan": 1.2
  },
  "chapters": [
    {
      "id": "01-opening",
      "label": "Opening",
      "eyebrow": "Chapter 1",
      "title": "A concise title",
      "subtitle": "Place or phase",
      "accent": "#B85C3C",
      "copyPosition": "left | right | bottom | center",
      "span": 4.6,
      "linger": 0.35,
      "paragraphs": ["Short paragraph one.", "Short paragraph two."],
      "tags": ["Source", "Theme"],
      "still": "assets/images/scenes/01-opening.webp",
      "shot": {
        "intent": "What this shot has to make clear",
        "framing": "Shot size, angle, subject placement, negative space",
        "motionNote": "Intended movement for a future filming or animation pass"
      },
      "clip": "assets/video/dives/01-opening.mp4"
    }
  ],
  "connectors": ["assets/video/connectors/01-opening-to-next.mp4"],
  "sources": [{"label": "Source title", "url": "https://example.com"}]
}
```

Requirements:

- `id` values are unique, filename-safe, and stable. Reject anything outside `[A-Za-z0-9][A-Za-z0-9._-]*`.
- `style` controls art direction; `ui` controls header, panel, typography, and navigation. Do not infer one from the other.
- `mediaMode` is `images` or `video`, and every new project writes it. An explicit `images` always wins, so a leftover `clip` field cannot make an image project load video. When the field is absent, treat the project as video only if it actually declares clips or connectors; otherwise treat it as images and ask the user to add the field. Reject unknown values.
- `lang` selects the interface strings and the `html lang` attribute. `zh` and `en` are the supported interface languages; the content follows the user's language.
- `crossfade` is the dissolve window in viewport heights for the arriving scene. It defaults to `0.8` in image mode and `0.14` in video mode, because a frame-matched video seam only has to hide the join while two unrelated stills have to dissolve. Lower it toward `0.2` for a crisper cut, raise it for a slower blend.
- `drift` is the still's zoom range across one chapter; even chapters zoom in, odd chapters zoom out. It defaults to `0.16` in image mode and `0.06` in video mode. Keep it modest: every step of zoom also crops the frame, so large values push subjects out of the safe area.
- Keep paragraphs short enough to display together at the minimum supported viewport. One chapter shows one complete, static copy block.
- `copyPosition` is optional. Choose it against the scene's focal subject and safe negative space.
- `span` is measured in viewport heights, not seconds. Larger values give the chapter more reading distance. It must be a finite positive number.
- `linger` (0–0.6) holds the middle of a chapter's scroll range still so the copy can be read.
- `still` is required in both modes. In a video project generated by `scripts/agnes_video.py --write-stills`, it is the clip's own first frame.
- `clip` is required in video mode, and is absent or ignored in image mode.
- In video mode, `connectors.length` is `chapters.length - 1`. Use `null`, or omit a connector the user explicitly accepted as a visible cut.

### Drafts, stable IDs, and review state

During the story-draft stage, `still` may name the expected project-relative image path before that file exists. This keeps the final story shape and chapter-to-asset mapping visible without inventing a placeholder. `verify_media.py --allow-missing` may be used for assembly checks at this stage only; formal media validation and `export_storyboard.py` remain strict and require every declared still to exist.

The displayed chapter number comes from the current array order. The chapter `id` is the stable identity used for production records, prompts, image files, and local revisions, and must not be renamed just because chapters are reordered. A user's “chapter 3” therefore maps to the third current chapter first, then to its stable ID before any file is changed.

Workflow state, confirmation decisions, revision numbers, authorization notes, and accepted-image provenance belong in the human-readable `docs/production-spec.md` and `docs/image-qa.md` records when those files exist. They are not part of the frontend runtime contract and do not require a second state JSON. A long-story review copy may be saved as `docs/review/story-draft.md`, but it is a read-only derivative of `content/story.json`, never a second editing source.

### `.motion-state/review.json` (stage executor state)

When the project carries `scripts/motion_stage.py`, this private file records the minimum machine state for the staged gates (`schema_version: 3`, `workflow_protocol: 2`). It never copies story content; `content/story.json` stays the only source of chapters and copy. A missing file never means "already accepted". The preview server never serves `.motion-state/`, and `init_project.py --force` preserves it.

| Field | Purpose |
|---|---|
| `schema_version` / `workflow_protocol` | State format and workflow protocol versions |
| `project_id` | Distinguishes stories; another project's acceptance never transfers |
| `binding` | The project root this state belongs to; a copied state cannot authorize another project |
| `interaction_mode` / `delegation` | Collaborative or explicit delegation, and the delegated stage scope |
| `phase` | Current execution phase |
| `story_review` | The shown story package: id, content baseline, sample list, display record |
| `visual_review` | The shown sample package: id, per-sample file digests, content baseline, display record |
| `revision` | The currently authorized local change, its chapters, and where the run must return to |
| `approvals` | Scope, linked package, real message or event reference, record source, and trust level; the **newest** record for a scope is the one that stands |
| `operations` | Every image attempt: committed, completed, failed, unknown, skipped, reconciled, plus the bytes it placed and the revision it belonged to |
| `generation_limits` / `total_provider_calls` | The authorized call ceiling and what has actually been spent |

Each package records its baseline by **dimension** — chapter order, per-chapter copy, the style basis, and the story metadata are stored separately — so a refusal names what moved and an authorized change cannot hide a different kind of change. Chapter order, a new style basis, and a metadata change can never be waved through by authorizing chapters one at a time; they retire the package and need a fresh confirmation.

Phases and their allowed image operations: `drafting` (none), `awaiting_story_review` (none), `sampling` (only whitelisted `sample_ids`), `awaiting_visual_review` (none beyond authorized sample revisions), `producing` (remaining missing or authorized-revision assets), `delivered` (only explicitly authorized local revisions). The executor checks the whole batch before calling the runner: a batch mixing approved and unapproved targets is rejected whole with zero real calls.

A withdrawal is a decision too: recording `--decision changes-requested` for story, visual, or delegation becomes the newest word on that package, so the earlier accept stops authorizing production immediately and the phase falls back to the first gate that no longer has a decision behind it.

A revision is bound to the change it covered. It records the chapter digests as they stood when the decision was made, plus the style basis, the story metadata, and the chapter order it was taken on — so a later edit to the same chapter, a restyle, or a retold meta is a different change needing its own decision, and with B still pending that decision is the only thing that can authorize a run; and a replaced sample file counts only when a run of a revision that authorized that chapter produced exactly the bytes now on disk, so a manual overwrite afterwards is still refused. A revision never rewrites a package baseline, and it stays open until every chapter it authorized has been produced — a failed call leaves that chapter still owed, and a chapter whose file landed before the process died is recovered from its persisted operation rather than waited on forever — including, for a derived page asset, the refreshed WebP.

A revision while B is still pending sends the run back to `sampling` with the sample package retired: confirmation A stands, and B must be rebuilt and asked again.

Review packages carry digests over the normalized JSON's effective fields, the actual image files, and the reference relationships — not over a hand-editable `r1` label. Overwriting a file changes its digest, so an old B cannot keep representing new images. Whitespace, JSON formatting, line endings, log timestamps, and state-field-only changes do not invalidate a creative confirmation. Digests only detect change: a digest or approval file the Agent writes does not become a trusted user-confirmation source. A decision recorded by the model from the conversation is `agent-recorded`; only a host-verified user event rates higher.

### Masters, page assets, and in-doubt calls

Generation always targets the lossless **master**: a chapter declaring `assets/images/scenes/03-cottage.webp` gets `03-cottage.png`, because the runner names its output from the format it produced. The page asset is derived afterwards by `make_posters.py`, so `status` and the run results report `needs_page_copy` beside `needs_generation`, and a chapter is never sent back to the model just because its WebP is missing. Existence is not freshness: a page asset older than the master beside it still counts as needing a refresh, because shipping it would show the reader a picture that was already superseded. A project that already has usable WebP with no master is left alone.

Each attempt is written to `operations` with its quota **before** the request is sent. A process killed mid-flight therefore leaves a `committed` record, which is treated as an unknown result on resume: nothing is resent until `status` is read and `--retry-unknown <operation-id>` names the reconciled call explicitly, and the refusal lists any finished file still sitting in `tmp/staged/` so a paid image can be recovered instead of bought twice.

The project lock is an exclusive lock the operating system grants to the owning process and releases the moment that process exits, however it exits. Two processes can therefore never be inside the executor at once — the second reports `project_locked` with zero provider calls — and a crash leaves no stale lock to break, because ownership never rests on the file's age or contents. The lock file is kept only as a readable descriptor of the current holder (pid and start time) and is never unlinked.

### Path rules

Media paths are project-relative. Reject absolute paths, drive-letter paths, UNC paths, and `..` traversal; after resolving symlinks the target must still be inside the project. Import a user-supplied image into `assets/images/` before referencing it, so the delivered page never depends on the user's machine layout.

### Stills and web images

`assets/images/scenes/*.png` holds the lossless SenseNova master, generated at `--image-size 4k` (4096×2304 for 16:9). When a WebP page image must be created or refreshed from that master, `scripts/make_posters.py` uses the project's recorded width: 2560 is the default for a new asset, while `--max-width 4096` preserves an established 4K page asset. Do not rerun the default against an existing project whose page width is already recorded as 4096. Compression never overwrites a master. Record and verify both dimensions; a 4K master alone does not prove the browser displays a 4K resource. An image project may reference an existing WebP when no master exists, and should skip compression rather than fail; converting a lossy WebP to PNG does not recover the original master.

A display poster is a different artifact with its own section below. Never point `make_posters.py` at a poster request.

### Shot direction (optional)

`shot` carries the direction for one chapter's image. It is entirely optional: a chapter without it is complete and valid, the page ignores it, and older projects never need it added. It exists so `exports/storyboard.md` and `exports/storyboard.html` can state what each shot is for, and so a later clip prompt has something to start from.

| Field | Purpose | Constraint |
|---|---|---|
| `intent` | What this shot has to make clear | Short; do not paste the chapter's paragraphs |
| `framing` | Shot size, angle, subject placement, and negative space | Describe the still that exists |
| `motionNote` | Movement intended for a filming or animation pass | Descriptive only: it never triggers generation by itself and is never presented as already produced |

- Each field must be a non-empty string when present. Unknown keys inside `shot` are ignored, so a project written for a later version still validates and exports.
- Shot numbers come from chapter order; `id` remains the stable identity. `exports/` lists both, so a numbered shot always maps back to one chapter.
- `span` stays a reading and scrolling distance in viewport heights. It is never rewritten as video seconds, and the storyboard deliberately omits it so no one reads pacing as duration.
- In a video project, `motionNote` is the natural first draft of the clip's prompt and `framing` states what must stay consistent. See [agnes-video.md](agnes-video.md).

## `exports/storyboard.md` and `exports/storyboard.html`

Both files are generated from `content/story.json` by `scripts/export_storyboard.py`; neither is a second source of truth. Edit the story data and export again.

- The shot list follows chapter order, and both documents show the same shots, the same copy, and the same sources.
- Media references are project-relative from inside `exports/`, so the Markdown reads correctly in an editor and the HTML displays its images without a server or any fetch.
- Every declared still must exist before either file is written. A missing or unreadable still fails the export; there is no allow-missing option, because a storyboard pointing at absent images is a broken deliverable. A "待配图" draft is a review artifact and stays out of `exports/`.
- The HTML is a static, print-ready document. It does not share the story page's scrolling stage or runtime, and it adds no JavaScript. Its print styles keep the still beside its copy so a shot is never split across pages.
- Only the exported deliverables listed under `SERVED_EXPORTS` in `scripts/project_model.py` are reachable from the preview server. The Markdown and every other file under `exports/` stay private.

## `exports/story-poster.png`

On request only, and produced by the infographic workflow — never by `scripts/make_posters.py`, which merely compresses stills for the page. Its brief is derived from confirmed story content: the title, the accepted still that carries the story, two to four short key facts, and an explicit ratio and size. Keep the long Chinese copy in the page and the storyboard; the poster carries only a few short fields. State the real dimensions and file path in the delivery, and confirm the Chinese text against the brief.

When more than one visual direction is viable, deliver the alternatives alongside the selected poster as `exports/story-poster-clarity.png` and `exports/story-poster-photo.png`, so the choice can be made by looking at images instead of reading descriptions. All three are delivered images of the same story, not drafts to discard.

A poster whose name differs from these defaults is still a deliverable — it just is not previewed over HTTP, so open it directly or rename it.

## `prompts/video-manifest.json`

Video projects only; an image project never creates this file. The manifest governs production while `content/story.json` governs what the page loads, and `scripts/verify_media.py` checks the union of both.

```json
{
  "provider": "agnes",
  "model": "agnes-video-v2.0",
  "duration": 4,
  "resolution": "1080p",
  "ratio": "16:9",
  "target_width": 1920,
  "target_height": 1080,
  "fps": 24,
  "crf": 23,
  "anchor_image_size": "2k",
  "dives": [
    {
      "id": "01-opening",
      "anchor_mode": "generate",
      "anchor_prompt": "prompts/video/anchors/01-opening.txt",
      "first_frame": "https://…  (only for anchor_mode url)",
      "prompt": "prompts/video/dives/01-opening.txt",
      "output": "assets/video/dives/01-opening.mp4"
    }
  ],
  "connectors": [
    {
      "id": "01-opening-to-destination",
      "from": "01-opening",
      "to": "02-destination",
      "anchor_mode": "reference",
      "prompt": "prompts/video/connectors/01-opening-to-destination.txt",
      "output": "assets/video/connectors/01-opening-to-destination.mp4"
    }
  ]
}
```

- `model` selects the provider model and must be one of the ids in [agnes-video.md](agnes-video.md): `agnes-video-v2.0` for high-definition clips, or `agnes-video-2.5-flash` when reference images or a last-frame-only anchor are needed. The pipeline refuses an unknown model rather than substituting one.
- `duration`, `resolution`, `ratio`, `target_width`, `target_height`, and `fps` are the delivery target. `scripts/agnes_video.py` normalizes every downloaded clip to exactly these values, and `verify_media.py` checks them.
- Each model's own limits are enforced before any provider call: v2.0 takes any short-side resolution or `WxH` and aligns frames to `8n+1` (at most 441), while Flash is fixed at `720P` and whole seconds from 4 to 12.
- `crf` is optional and defaults to `23`. It is the quality-versus-payload knob for the local normalization step: at 1080p a transition clip drops from 11.0 MB to 7.6 MB at `26`, or to 4.1 MB at `30`. See [agnes-video.md](agnes-video.md).
- Anchor images are generated by the project's own SenseNova skill; the video provider only animates them. `anchor_image_size` (optional, `1k`/`2k`/`4k`, default `2k`) sets their resolution for the image call.
- `anchor_mode` decides what media the clip sends, because the video models take no local media:
  - `generate` — SenseNova creates an anchor from `anchor_prompt`, and its public URL becomes the first frame. The template selects this for dives; the URL is recorded in `.motion-state/video-anchors.json`.
  - `reference` — public reference images guide the clip. A connector with no explicit list borrows the two chapters' recorded anchor images, which needs no host.
  - `url` — `first_frame` and/or `last_frame` are used as-is; each must be a public HTTPS URL the user controls. Use it to pin one end of a seam exactly.
- Every clip must explicitly select `generate`, `reference`, or `url`. Missing modes and `text` are rejected before any provider call; unavailable anchor URLs are errors, not permission to generate without images.
- A connector cannot use `generate`: it joins two existing chapters. Use `reference` or `url`.
- `reference_images` overrides borrowed anchors: v2.0 accepts one image (`ti2vid`) or two images (`keyframes`); Flash accepts up to five. Flash rejects video references and refuses keyframe and reference inputs in the same request.
- `.motion-state/video-anchors.json` is private run state: it records the provider URL each generated dive starts from, and `.motion-state/` is never served, never a deliverable, and survives a `--force` initializer run. Regenerating a dive rewrites its entry; a connector that runs before its dives reports the missing anchors instead of guessing.
- Keep the same `id` in the manifest, the story's `clip`/`connectors` entries, and the file name, so the page, the pipeline, and the files cannot drift apart.

### Frozen alternative: the Ark/Seedance manifest

An earlier design targeted Ark with `doubao-seedance-2-5-260628`, a `conditioning_mode` of `reference_images` or `first_last`, and a boundary-frame cache under `assets/video/frames/`. That path was never enabled and its script still carries a known duplicate-billing retry defect. It is documented in [seedance.md](seedance.md) and is not the current contract; do not mix its fields into an Agnes manifest.
